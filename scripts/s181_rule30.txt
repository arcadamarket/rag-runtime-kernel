Rule 30 (DESIGN-ASSET-ROUTING -- S178 origin; operator directive: "make it available not only for the currently designed sibling, but also for all other ones coming up". ROUTE RE-POINTED S181 by operator ruling). SCOPE: this rule is INHERITED BY EVERY CLONE via the migration/transplant protocol -- it is kernel-owned governance, not per-project content, so a sibling spawned five projects from now boots with it already loaded. WHY IT EXISTS: S178 ingest sources 14-17 recorded three independent runs of the operator's ten-step business-launch prompt. All three delivered steps 1-9 (copy, keywords, meta, headers -- the commoditised part) and ALL THREE DIED AT STEP 10, the only step that produces artifacts. Zero logos, zero flyers, zero business cards, zero banners, zero ZIPs across three attempts, and the operator's own note on source 17 reads "designed to actually deliver what ChatGPT promised but never provided". The pipeline is draft -> [GAP: package] -> [GAP: distribute]; this rule addresses the FIRST gap. THE VISUAL-ASSET CLASS (the trigger set): logo, favicon, flyer, business card, banner, cover image, avatar, social profile image, one-pager, mockup, slide deck, landing-page visual comp, branding sheet (palette + type). THE ROUTE (S181 ruling -- supersedes the S178 designation of Claude Design): when a deliverable falls in this class, the agent MUST route it through the deployment's REGISTERED design route, which is the locally installed ui-ux-pro-max MCP, BEFORE hand-rolling HTML/CSS, before generating SVG by hand, and before declaring the asset infeasible. If the route is NOT taken, the agent states WHY in one line and records it -- an unexplained bypass is a Rule 30 violation. WHY THE ROUTE MOVED, and the general principle it encodes: the S178 designation named Claude Design, a research-preview UI product with NO public API and NO MCP server, so the kernel could never invoke it -- the rule routed to a place the runtime cannot reach, and the S179 blueprint then found the clone already carried a programmatically reachable design MCP, leaving a tracked item and a blueprint in flat contradiction. THE DETERMINISTIC ROUTE MUST BE PROGRAMMATICALLY REACHABLE. A product the agent can only drive by hand is a FALLBACK, never the route; Claude Design remains available as that manual fallback and must be recorded as a bypass when used. INHERITANCE: a clone that does not carry ui-ux-pro-max MCP registers its own reachable equivalent and records it before shipping any asset in the class -- an unregistered route is a Rule 30 violation on its first use, not a grace period. WHAT THIS RULE IS NOT: it is NOT authority to move the behavioural layer, control prompts or any governance state into a design tool, Skills, or any other vendor UI configuration -- that would create exactly the side store drift_audit rejects and a second source of truth outside the RAG (see rejected item BEHAVIOR-LAYER-SIDE-STORE-RISK, S178). The RAG remains the single source of truth; the design route is a DELIVERABLE-PRODUCTION tool and nothing more. ENFORCEMENT STATUS -- READ THIS: as written, this rule is PROSE, and by the project's own GATE-OR-HOPE-PRINCIPLE (S178) a rule that can be violated silently is a hope, not a rule. Rule 23 sat as prose for 24 sessions and failed until it became a machine gate at S178. The mechanical half is tracked as DESIGN-ASSET-ROUTING stage 2: a declared deliverable-class field on the close, which refuses the seal when a visual-asset deliverable is declared with no design-route attestation. Until stage 2 ships, this rule is operator-detected, not machine-enforced, and it should be treated with the suspicion that status deserves.
